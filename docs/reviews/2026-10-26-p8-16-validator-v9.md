## 1. The build

- **g1f** (pass 1 of `validate`).
  - A row's grounding block is still the claimed block when it prints the name, else the
    first print at or after the cursor.
  - When there is no such print, the row now takes the print nearest its claim, not the
    page's first. The reference point is the cursor when the row claims nothing, and ties
    go to the print above.
  - Then, as before, a print repeated right below moves to its last copy.
- **G3.** `grounding_tokens(text)` is `block_tokens(text)` together with `block_tokens` of
  the text with a lowercase letter glued to an uppercase one split ("PalomaHerredura" →
  "Paloma Herredura").
  - It is a union, as v6's glued-integer split is, so it only adds groundings.
  - Only [5]'s name grounding uses it. `output.split_listed`, a repair, keeps `block_tokens`,
    so `repairs-v9` behaves as before. P8-15's prototype patched the module attribute, which
    also left the repair alone.
- **Version.** `VALIDATOR_VERSION = "validator-v9"`. The length is unchanged, so
  `method_version` stays 126 characters. The module docstring now says v9 and describes both
  rules.
  - The JSON-LD stream's version also names the validator (`jsonld-v1;validator-v9;…`), so
    applying v9 re-interprets JSON-LD pages too.
  - Two tests pin the version strings (`test_menu_extraction.py`) and are updated.
- **Tests** (`test/test_parsing_validator.py`):
  - `test_v9_a_name_glued_to_its_description_grounds_on_its_own_block` (Paloma, plus the
    union both ways);
  - `test_v9_with_no_print_after_the_cursor_a_row_takes_the_print_nearest_its_claim` (a dish
    printed in two sections: a claim under the second print, and a copy claimed under the
    first with the cursor past both);
  - `test_v9_the_print_nearest_the_claim_prefers_the_one_above_on_a_tie`.
- **Mutation check** (`var/p8-16/mutate.py`): **4 of 4 killed**. The mutations are G3 off,
  the first-print fallback restored, nearest the cursor instead of the claim, and the tie
  going below.
- **Equivalence.** On the 793 dev pages plus the 863 corpus page texts, every `llm_stream`
  verdict equals P8-15's `ground.py` variant `g1f+g3` on `validator-v8` (item, amount,
  variant, decision, reasons, both locators). 0 of 1,885 page texts differ. So Amendment 30's
  P8-15 table holds for the build.

## 3. The invariance suite (ADR-0017 item 1): failed

P5-24/25's `inv_tune.py` runs on the 218 tuning pages (labels-v9). It writes perfect gold
output in 15 meaning-preserving styles and counts gold prices whose status flips. v8 is the
baseline.

| | v8 | v9 |
|---|---|---|
| Flips, all styles | 6,638 | 6,658 |
| Added page/style pairs | — | **8** |

The added pairs are `claim_next` and `claim_price_block` on four pages (`var/p8-16/stage/`,
`var/p8-16/inv_split.py`, `inv_case.py`):
- **g1f, 9 per style.** On `8db407b1e8ef` (8) a lunch and a dinner menu print the same dishes.
  The suite writes rows grouped by section, so lunch and dinner rows interleave.
  - With the claim moved one block below the name, the dinner "Gyro Wrap" row has no print at
    or after the cursor.
  - v8 sent it to the page's first print, the lunch menu: the wrong dish, but it kept the
    cursor in the lunch menu. v9 sends it to its own print, b0272, which is right.
  - The next lunch rows, whose claims also miss, then follow the cursor into the dinner menu
    under the unchanged cursor rule.
  - `4b9d6bb201da` adds 1 the same way.
- **G3, 3 per style.** On `49b6a15a40ee` (2) and `00f349e12f5b` (1) it is the glued-copy case
  above: a description glued to the next dish's name gives that dish an earlier print.
- **A narrower G3 does not help.** Glued words split only in the row's claimed block (`v9c`)
  adds more: 9 pairs, 6,638 → 6,685.
