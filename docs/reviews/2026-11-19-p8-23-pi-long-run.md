## 4. The long recrawl (step 5)

`var/p823/run-loop.sh pi` on the Pi against `helios_work`: per batch, `menu_pipeline.run --limit 50
--render` (under `xvfb-run`), then `menu_pipeline.extract` (every due page; saved answers reused,
changed texts sent to the model), then a progress line. A `STOP` file ends it between batches;
both CLIs commit per URL / page, so a re-run resumes. **Mode `pi`: no thermal pause** (owner, during
the run: "on the orange pi there should be no pause line, add a toggle for pi/laptop mode for next
time"; mode `laptop` keeps the 85 °C pause and the llama-server watchdog). 1,746 menu-page URLs were
due (every one fetched 2026-10-27/28 or earlier).

### Finding: a restored dump blocks Menu writes on another cluster (`menu.admission_fence`)

Batch 1's extraction stopped on its first page: `SerializationFailure: Menu admission snapshot is
stale`. `menu.lock_admission()` keeps the last admitting transaction id in the sequence
`menu.admission_fence` and refuses a writer whose snapshot can't see it. `pg_restore` carries the
sequence value over: `helios_work` held the laptop's 915,058 while the Pi's cluster was at
transaction 27,739, so every admission would have failed until the Pi's counter passed the
laptop's (about 890,000 transactions). Earlier Pi restores never hit it because the Pi never wrote
Menu pages. **Fixed for this run** (work database only): `setval('menu.admission_fence',
txid_current())` on `helios_work`, then the loop resumed; batch 1's pages stayed due and were
extracted in the next batch. Restoring a Pi dump into `helios_laptop` is safe (its fence value is
below the laptop's counter); the reverse, or any restore onto a younger cluster, needs the same
reset before Menu writes. Not changed in code (a migration-owned function): an owner question.

### Finding: most refetched pages change, and a changed text is extracted whole

Batch 1 (50 URLs, 92 records): 60 changed + 2 new Versions, 30 unchanged. Of 18 changed texts with an
older Version, the median change is 33 lines; real menu changes (new dishes, new prices) sit next
to churn: "ORDER NOW" → "Order Now", a byline's capitalisation, a footer link, CDT → CST, and on
delivery platforms ratings, preorder times and neighbourhood lists (Uber Eats' Chick-fil-A pages:
24–27 chunks each, changed throughout). Reusing saved answers per chunk instead of per page would
have skipped **30 of 146 chunks (0.21)**: chunks are cut by size, so an early insertion moves every
later chunk boundary. At 6 pages/h a batch of 50 URLs costs about 10 hours of extraction.

## Appendix: follow-up measured while the Pi ran (owner: "work next task")

P8-22 left one Gold finding open: an Amazon grocery catalog is two venues' menu (710 Gold rows,
234 of them "Unable to add item"), and a Walmart page another's (14 rows). Read-only measurement
on `helios_laptop` (post-validator-v12); **nothing changed in code or data.**

**What they are.** Skyrocket Coffee and Prime Tea Shop list Amazon storefronts as their Overture
website (`amazon.com/shop/skyrocket_coffee`, `amazon.com/primetea`); discovery treated amazon.com
as their own site and the page check accepted the grocery category page it reached
(`amazon.com/fmc/everyday-essentials-category`). The Walmart venue ("Walmart Bakery") gets the
store's meal-planning page.

**Four generic rules, none clean** (the owner prefers automated rules to manual entries):

| Candidate | Catches the catalogs | Cost |
|---|---|---|
| The page doesn't print the venue's name | yes | 219 of 2,805 own-site menu records (7.8%, 6,649 Gold rows) don't, mostly legitimate: JuiceLand locations named by branch ("Burnet Rd"), legal names ("Sogno Restaurants Llc"), spellings ("Rice2Go") |
| A deep-link website's menu lies outside the website's path | yes | 681 of 732 deep-link records: a chain's location page legitimately leads to its `/menu` |
| One own-site menu URL saved by venues whose names share no token | yes (Amazon) | 35 of 401 shared URLs, mostly name variants ("Fonda San Miguel" / "Cuisines Of Mexico Inc") |
| A website host shared by many unrelated venues | no | amazon.com is the website of only 2 Austin venues; walmart.com's 12 are all "Walmart Bakery" (a chain shape) |

**Owner question:** leave the 3 records (724 rows); have the page check learn store catalogs
(needs labelled catalog negatives); or accept one exception to "no manual entries" for general
marketplaces. *Recommended:* the page-check route, measured on the next precision sample, since
catalogs are a page-shape problem.

**Found on the way, for the record:**
- **Articles as menus:** 59 own-site menu records are blog or news posts, among them Chick-fil-A's
  "9 nutritious Chick-fil-A menu picks" for 34 venues, Freddy's (6), Bill Miller's attachment page
  (7) and Long John Silver's (5). They put almost nothing in Gold (24 rows, all on Cotton Patch's
  "daily lunch specials" post), but they fill those venues' menu slot with an article's items. This
  is the verifier precision gap P8-21 measured (hubs and articles, precision 0.890). A path-token
  veto ("blog", "news", "stories", "article" in `menu_url._BLOCKLIST_TERMS`) would stop new ones
  at candidate selection, but a saved URL is re-verified by the page check alone, so the 59 would
  stay until re-verification gets the same rule (a withdrawal reason, ADR-0015): an owner question,
  not built.
- **Another business's website:** Brennas Deli → brennanshouston.com (Houston), The Kitchen
  American Bistro → thekitchen.com's Boulder menus, Luisa's Patio → a "cafeross" page. place-v2
